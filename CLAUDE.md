# GRANDXGAMER (repo: pocketOS, branch `grandxgamer`)

The app for the GRANDXGAMER gaming café (owner: Shashank): the counter floor (PC1–PC5, PS5), staff clock-in and salary, event slot bookings (GTA VI launch first), the cash drawer, money and shared passwords. **This branch is its own product**: it never merges into `main` (eChopdo, the family app) and `main` never merges here; push only to `grandxgamer`. Built from the eChopdo code (React 19 + Vite, Supabase, plain CSS in `src/index.css`) with Will, bank SMS capture, the phone widget pairing and family households removed. **Never put eChopdo family data in this branch**, and never real customer names/phones in code or tests.

Plan and prototype the owner approved for feedback (11 Oct 2026): https://claude.ai/artifact/Lo72U61SZWdZF8WRmMy6vD — phase 1 (this) = shop without Excel; phase 2 (before 19 Nov) = customer logins (mobile + passkey, added at the counter), live availability, self-booking; phase 3 = tournaments, Excel export, Android app (TWA + self-update like eChopdo's, package to be `app.grandxgamer`; `android/` is still the eChopdo app, untouched).

## Shop module (`src/components/shop/`, data in `src/lib/shop.js`, schema `supabase/shop.sql`)

- Tables (all `household_id`, RLS "shop reads" = `private.my_household_ids()` (owner + staff); settings/shifts writes and all deletes = `private.my_admin_household_ids()` (owner only); sessions, cash, event bookings writable by staff): `shop_systems` (name, kind PC/PS, active), `shop_rates` (kind, minutes, price), `shop_sessions` (one row per customer on a system: base/total minutes, gaming/extend/F&B before/while/discount, paid_cash/paid_online/owed, status running/closed/cancelled; unique running per system), `shop_shifts` (clock in/out; staff only via rpc `shop_clock(p_household, 'in'|'out')`; admin edits), `shop_cash` (open / in / out / count), `shop_events` + `shop_event_bookings` (capacity trigger `private.event_slot_capacity`). `shop_sessions` + `shop_event_bookings` are in the realtime publication; `useShop` subscribes so every phone's Floor updates.
- Today (admin) has ‹ › to step back through past days (`useDay`): totals, hours by system, the day's **Sessions** list (the old sheet's rows) and the drawer. 9–11 Oct 2026 were imported from the owner's Excel screenshots (note "Imported from the Excel sheet"; 9 Oct "PC" row has no system id).
- Pricing: `priceFor(rates, kind, minutes)` = cheapest mix of rate-card items that covers the time (PC 30 min ₹50 + 1 hr ₹80 → 1.5 hr ₹130, 2 hr ₹160 — matches the owner's old sheet; PS5 1 hr ₹100). Amounts are stored on the session, so changing rates never rewrites old bills. Extend = price(new total) − gaming amount. Money on shop screens is whole rupees (`rs`).
- Drawer (`dayTotals`): opening cash + cash collected (sessions' paid_cash, cash event advances, cash in) − cash out = should be in drawer; online shown separately; a count shows short/extra.
- **Events are settings, not code** (user's rule): name, PS/PC, first/last day, open/close time (close after midnight works), slot length, systems per slot, price, advance, open/closed. GTA VI launch (19–23 Nov 2026, 2-hr PS5 slots, ₹200, ₹100 advance) is just the seeded first event (`private.seed_shop`).
- Staff tab: month salary = Σ shift hours × hourly rate; add login (admin types the 6-digit PIN — pre-filled with a random one — and rate; shows the details once, copy), **Edit** (name, hourly rate, optional new PIN), remove, "Clock out now", edit/delete a shift.
- **Swipe** (user's request): in Shop, swipe left/right anywhere moves between tabs (`ShopModule`, `useSwipe` with `ignore: '.gx-dateswipe, .gx-scroll'`); date areas (`.gx-dateswipe`) swipe the date instead — Today's day header + total card (‹ › days), Events' slot list (event days), Staff's month header (months back). Sideways chip rows (`.gx-scroll`) only scroll.
- Money module = eChopdo's Budget (Home, Entries, Plan, Dues, Hisab), admin only; no household chip or Households/SMS-card settings (one shop; the chip only shows with 2+ households); the **Cashbook** tab (was Hisab; code ids stay `hisab`. **Never show the word "Hisab" or other Gujarati terms in the UI** — the owner isn't Gujarati; plain English: Cashbook, Shop book, Event books) is the shop's: the main book (kind `daily`) is shown as **Shop**, occasion books are **Event books** (🏆 a tournament, a launch, a renovation), views By day / Calendar / Summary, and its defaults in `hisab.js` are café categories (Snacks stock, Cold drinks, Electricity, Rent, Staff salary… / Gaming, F&B sales, Events); seeded with café categories (Gaming, F&B sales, Events, Rent, Electricity, Internet, Staff salary, Snacks stock…) and accounts Cash drawer / Bank / UPI.

## Locking, one fingerprint
- Once the vault exists, the **whole app** sits behind the vault unlock: `Shell` shows `UnlockScreen` (VaultGate, auto fingerprint prompt) while `vault.status === 'locked'`, so Shop and Money are protected too, and one fingerprint opens Shop, Money and Vault — never ask twice. The old separate app lock (`useAppLock`) only applies when no vault is set up, and is switched off automatically once one is (it caused the double prompt).
- Fingerprint is per phone *and* per web address: `fingerprintHere(unlockers)` (useVault.js) checks this origin's `pocketos.vaultCredential`; the unlock screen only offers/auto-prompts that one. After an unlock by master password/recovery code on a phone without one, `useOfferFingerprint` (App.jsx) asks once "Use your fingerprint next time?" ("Not now" remembered in `pocketos.fingerprintOfferDismissed`). ⚙ Settings has a **Security** card for the owner (fingerprint on/off for this phone, **Change master password** — asks for the current one first, then `vault.changePassword`, which only re-wraps the key).
- Idle auto-lock counts activity in every module (`onPointerDownCapture`/`onKeyDownCapture` on `.shell`); locks after 5 min idle or 60 s in the background, or via a module's lock button.
- **Reload / pull-to-refresh doesn't re-ask** (`src/lib/vaultSession.js`): on unlock the vault key is saved for this tab only — encrypted with a random non-extractable AES key kept in IndexedDB, the blob `{ uid, iv, data, active, hiddenAt }` in sessionStorage (cleared when the PWA is closed). On load `useVault` restores it unless it's past 5 min idle / 60 s background; `lock()` and sign-out clear it. Closing and reopening the app always asks. Members' `useAppLock` does the same with a plain `pocketos.appUnlocked` timestamp in sessionStorage.

## Back button (installed PWA)
- `src/lib/backNav.js`: `useBackButton` (once, in Shell) keeps one extra history entry so Android back lands in the app. Back closes the top overlay first (dialog → menus → will preview → last `.modal-bg`, by DOM convention), then the highest registered `useBackAction` (level 2: a module's tab → its first tab; level 1: module → Budget), then at the root shows "Press back again to close" and a second back within 2 s exits. New overlays should use `.modal-bg` / `.dialog-bg` so back closes them.

## Vault (zero-knowledge)
- **Never send plaintext to Supabase.** One random 256-bit vault key encrypts each item (AES-GCM, item id as associated data) in `src/lib/vaultCrypto.js`. Every field, including the item type, lives inside `vault_items.ciphertext`.
- **Item types** (LastPass-style) are defined in `src/lib/vaultTypes.js`: 19 types (password, passkey, secure note, contact, payment card, bank account, driver's license, passport, government ID, health/insurance/membership, Wi-Fi, email, messenger, database, server, SSH key, software license), each with its field list. The form, detail view, list subtitle, search and quick-copy button are all driven from it, so a new type or field is a registry edit only. Items without `type` (saved before types existed) are passwords. Field labels match LastPass's, so LastPass secure notes import as typed items (`typedFromLastPassNote`). The UI is `src/components/VaultItems.jsx`: + opens a type picker (full-screen on phones), and filter chips appear once there's more than one type. **Folders** (the user's request — many LastPass imports): the item's `folder` (LastPass `grouping`, kept by the import; nested LastPass folders are `Parent\Child`, shown "Parent › Child") lives inside the encrypted item. The list is grouped into collapsible folder sections ("No folder" last; open ones remembered in localStorage `pocketos.vaultOpenFolders`); while searching it's one flat list with the folder in each subtitle. The item view has a **Folder** select (existing folders / No folder / + New folder…) that re-saves the item at once (`moveToFolder` → `vault.saveItem`); the form's Folder field suggests existing folders (datalist). Each folder header has a ✎ → `FolderSheet`: rename (subfolders follow), **merge** by picking/typing another folder's name (its exact spelling is kept), or **Remove folder** (items → No folder); `renameFolder` re-encrypts every affected item via `vault.updateItems` (batches of 10, one reload). Members only change their own items.
- The vault key is stored only *wrapped*, once per unlocker in `vault_unlockers`: `password` (PBKDF2-SHA256, 600k iterations), `recovery` (32-char Crockford base32 code → HKDF), `prf` (per-device fingerprint: WebAuthn PRF extension output → HKDF). Lose all three and the data is unrecoverable, by design.
- Fingerprint credentials (`src/lib/webauthn.js`) are PocketOS's own WebAuthn credentials with `rp.id = location.hostname`, separate from Supabase's sign-in passkeys, so they work on any origin (incl. localhost), but are per-origin. PRF needs Chrome on Android or Safari on iOS 18+. No server-side signature verification: the PRF secret is what decrypts.
- State lives in `useVault` (`src/lib/useVault.js`), called from `Shell` so switching modules doesn't lock. Key held in memory only (refs); auto-locks after 5 min idle or 30 s in the background.
- **App lock**: superseded by the vault gate (see "Locking, one fingerprint"). `src/lib/useAppLock.js` / `AppLockScreen.jsx` remain only for a login with no vault yet. Budget data itself isn't encrypted; the gate is a privacy lock.
- Extras in `src/lib/vaultTools.js`: TOTP (RFC 6238, base32 or `otpauth://`), password generator (rejection sampling, no look-alike chars), LastPass CSV import (parsed and encrypted on device), Have I Been Pwned k-anonymity breach check (only 5 hex chars of the SHA-1 leave the device), clipboard auto-clear after 30 s.
- Autofill into other apps/sites is impossible from a PWA. Users copy and paste.

## Conventions
- Data access happens directly in components via `supabase.from(...)`. Shared loaders are in `src/lib/useFinanceData.js`.
- **Code splitting**: every tab, the Vault screens and the Shop module are `React.lazy` in `App.jsx` (wrapped in `Suspense` with the matching skeleton); Recharts lives only in `src/components/Charts.jsx`, used through `LazyCharts.jsx` (same-size placeholder while loading). `preloadBudget()` fetches Home + charts while the unlock screen is up. Main chunk ≈ 500 kB (142 kB gz), was 1.09 MB. Don't import `recharts` anywhere else.
- Money and date helpers are in `src/lib/format.js` (INR / en-IN by default via env). `moneyShort` writes K / L / Cr for en-IN (ICU's compact form says "T" for thousand).
- After any schema change: add the SQL to `supabase/schema.sql`, apply it as a migration, then run the Supabase security and performance advisors.
